## 为什么选择 VKT CleanMate？

大多数清理工具只有一个"全部清除"的大按钮。所以很多人不敢打开它：点一下，所有网站的登录状态全没了。更糟的是，你按下去之前根本不知道它会清掉 3 个站点还是 3000 个。

VKT CleanMate 把"决定"和"执行"分开：

| 别的清理器的做法 | 代价 |
|---|---|
| 一个开关清掉一切 | 手滑一次，登录状态、Cookie、下载记录全没了 |
| 一个不写数字的确认框 | 按下去之前看不出这次要动多少东西 |
| 站点规则藏在正则输入框后面 | 没人愿意写，于是"安全模式"从来没人真用 |

| VKT CleanMate 的做法 | 结果 |
|---|---|
| **每次清理都先出预览表** | 给的是浏览器里的真实数字：命中站点、历史条数、Cookie 数、开了几类数据、保留期多长 |
| **免费版根本跑不了全清** | 免费用户不存在误删路径 —— 这是设计，不是提示 |
| **两个方向相反的名单** | 清理名单（"只清这些"，免费）与保护名单（"这些永不动"，付费） |
| **把做不到的写出来** | 写在界面上，也写在这份 README 里，而不是留给审核员去发现 |

一句话定位：**清理之前先让你看清要删什么，清理之后告诉你时间都去哪了。**

## 它能做什么、不能做什么

### ✅ 它能

- 按任意组合清理历史、缓存、Cookie、下载记录、表单数据、本地存储、IndexedDB、Service Worker 和密码。
- 把清理限制在你写下的域名上 —— 匹配域名及其子域名，不需要正则。
- 在全面模式下跳过你保护的域名。
- 按计划自动清理，且每种触发器可以带不同的数据范围。
- 每次清理后如实报告删掉了什么。

### ❌ 它不能

- 清掉 DNS 缓存、路由器日志、运营商记录或网站服务端日志。那些不在你的设备上。
- 恢复已删除的历史。Chromium 没有给任何扩展写入历史的接口。
- 清理其它浏览器的数据、其它配置文件，或者同步到别的设备上的那一份。
- 把历史、下载记录、表单数据、密码限制在单个站点。浏览器不提供这种能力，这四类只在全面模式下参与过滤，界面上就写在勾选框旁边。
- 保证「关闭浏览器时」一定执行。这是尽力而为：崩溃、强制重启或断电都可能让那一次落空。
- 清掉从未被保存的东西。只在无痕窗口里读过的页面，本来就没留下痕迹。
- 替代 VPN，或者抵御网络层面的监控。它是给你自己设备上的这个浏览器用的自助工具。

## 使用说明

### 第一次使用

打开弹窗，点「立即清理」。因为默认是精准模式、而清理名单还是空的，所以什么都不会发生 —— 这正是重点。先去 `Lists` 页加一个域名。

### 怎么填清理名单

- 弹窗里：**添加当前站点**，把正在看的域名加进去。
- `Lists` 页：输入 `example.com` 后点 Add。子域名自动覆盖，`www.` 会被自动去掉。
- 足迹页（Pro）："值得清理"建议和时间去向排行，每行后面都有一个按钮直接加进名单。

### 怎么配自动清理

`Cleaning` 页的五个触发器各有独立开关。开关下面的下拉框决定这一次清理的数据范围 —— `global` 表示跟随上面的勾选，选其它值则把这次清理限制在某个预设组合（历史 + 缓存、Cookie + 缓存、全部……）。

一个合理的起点：每 6 小时清历史 + 缓存，关闭浏览器时清全部，启动和空闲先关着，等你确认自己真的需要。

### 快捷键

| 按键 | 动作 |
|---|---|
| `Alt+Shift+C` | 按当前设置立即清理 |
| `Alt+Shift+X` | 立即清理，然后关闭所有标签页与窗口 |

两个都能在 `chrome://extensions/shortcuts` 里改。

## 工作原理

1. 触发器到点，或者你按下「立即清理」。
2. 后台 Service Worker 先算出域名范围：精准模式下是清理名单，全面模式下是"全部减去保护名单"。
3. 统计会被影响的内容 —— 站点数、历史条数、Cookie 数 —— 弹出预览表。**此时还没有删除任何东西。**
4. 你确认之后，勾选的每一类数据通过 `chrome.browsingData` 删除，每批最多 50 个 origin。
5. 域名规则会先展开成真实的 origin：`browsingData` 只接受 origin（`https://example.com`）而不是裸域名，也不会自己展开子域名。
6. 完成后通知你结果，记录本次执行时间，预览表在弹窗里随时能再看。

一个值得知道的实现细节：`browsingData` 的 `origins` 参数只对缓存、Cookie、本地存储、IndexedDB、Service Worker 和文件系统生效。历史、下载、表单数据和密码会完全忽略这个列表 —— 所以一旦勾上这四类，清理范围就是整个配置文件。界面里直接写明了这一点，没有假装它支持。

## 常见问题

**清理会删掉书签吗？**
不会。书签不属于 `browsingData`，扩展里也没有任何代码碰它。

**清 Cookie 会让我所有网站掉登录吗？**
精准模式下只影响你写进名单的域名。这也是免费版只跑精准模式的原因：全清是需要刻意做出的付费决定，而且要带着保护名单一起做。

**能只清某一个站点的历史吗？**
能。这需要可选的 `history` 权限，只在你预览或按站点清理历史的那一刻才申请，安装时不申请。

**会删掉同步到 Google 账户的密码吗？**
如果你勾上「已保存的密码」，浏览器会删除本地密码库，而已登录的配置文件可能把这个删除同步上去。这类数据默认关闭，界面上也用红色标出，原因就在这里。不需要就别勾。

**无痕窗口能用吗？**
无痕窗口关闭时自己就把数据丢了，没有东西可清。扩展也不需要访问无痕窗口。

**「关闭浏览器时」没执行？**
它是尽力而为。窗口数量归零时触发，如果浏览器在任务中途退出，清理会在下次启动后几秒内补完；崩溃、强制重启或断电会让那一次落空。

**会清别的浏览器或别的配置文件吗？**
不会。一个配置文件，一个浏览器，这台设备。

**为什么保护名单要收费？**
因为免费版刻意不提供全清。"全部清除"才是那个有风险的操作，所以安全网跟着它一起卖。

## 隐私说明

没有统计分析，没有埋点，没有广告，没有账号。扩展不读取页面内容，不记录按键，也不建立画像。设置存在 `chrome.storage.local`。专注足迹如果开启，只保存域名、时长、访问次数和一张小时分布图，30 天滚动过期，不存 URL，不存标题。整个扩展唯一的网络请求是向 `api.annmax1983.com` 校验授权，而且只在你粘贴密钥之后才发生。

**[📄 完整隐私政策](../privacy-policy.html)**

### 权限说明

| 权限 | 用途 |
|---|---|
| `browsingData` | 删除你选择的数据类型 |
| `storage` | 在本机保存设置与可选的专注足迹 |
| `alarms` | 定时任务，以及专注计时所需的每分钟心跳 |
| `tabs` | 识别当前域名，对正在看的标签页执行操作 |
| `windows` | 检测最后一个窗口关闭 —— 「关闭浏览器时」触发的依据 |
| `idle` | 可选的「空闲后」触发 |
| `notifications` | 清理结果摘要 |
| `history`（可选） | 只在你预览或按站点清理历史时申请 |
| `cookies`（可选） | 只在你按站点清理 Cookie 时申请 |
| `api.annmax1983.com` | 仅用于授权激活与校验 |

两个可选权限，正是全新安装时不会出现"读取浏览历史"红色警告的原因。

### 关于专注足迹

- 默认关闭，属于付费功能。
- 默认只在你打开足迹页时采集（靠一条长连接维持）；页面关掉就停止。
- Service Worker 里不能用 `setInterval`：会话在标签页/窗口事件里结算，再由每分钟一次的 alarm 兜底。
- 只保存 `domain`、`duration`、`visits` 和小时分布，不存 URL，不存标题。
- 免费用户看到的是授权说明卡，不会建立连接，因此什么都不会被记录。
